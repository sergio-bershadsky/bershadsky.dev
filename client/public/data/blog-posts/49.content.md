# Comprehension Debt: The Monday Playbook

> Six moves, no rewrite required, that start paying down comprehension debt while the feature train keeps running — beginning Monday.

You've read five parts of theory. Here's the part you forward to your tech lead. Six moves, none requiring a rewrite, that start paying down comprehension debt while the feature train keeps running — beginning Monday.

Now the calm-down, because the shout above ships with a constraint, and the constraint is real: nobody gets a refactoring quarter, so every move below is incremental, measurable, and survives contact with a deadline. There is also no new theory in this part — [Part 1](/blog/comprehension-debt-the-debt-nobody-booked) named the debt, [Part 2](/blog/comprehension-debt-frozen-context) showed why markdown can't hold it, and [Parts 3](/blog/comprehension-debt-boundaries-beat-willpower) [through](/blog/comprehension-debt-specs-with-a-failing-state) [5](/blog/comprehension-debt-metaframework) built the mechanisms. What's left is sequencing. Each move ships with an owner, a mechanism, and a metric, because a move missing any of the three is not a move, it's a listicle entry. Take the six headings below into your next engineering-leads meeting as the agenda; they were written to survive that room.

## Move 1: Measure Before You Medicate (Weeks 1–2)

Part 1 closed on the fairest critique this topic has received: comprehension debt stays [a metaphor until you attach testable diagnostics](https://www.fightforthehuman.com/we-need-more-than-a-metaphor-here-are-testable-diagnostics-for-comprehension-debt/). So attach them. Three numbers, all extractable from data you already have:

**Time-to-confident-change.** Calendar days from a new hire's start to their first non-trivial change merged without a senior hovering over the diff. This is the learnability of your system expressed in payroll units, and every onboarding buddy already knows the number informally.

**Orphan-module count.** Modules where the honest answer to "who can explain this?" is nobody. Not "who committed to it" — git knows that, and it increasingly answers "the agent" — but who can state what must never happen inside it. A rough count from memory is fine for week one; Move 2 makes it exact.

**Surprise rate.** The fraction of changes everyone agreed were trivial that produced an incident, rollback, or hotfix. Your incident channel is the ledger; you've just never read it as one.

**Owner:** the tech lead. **Mechanism:** a spreadsheet — genuinely, a spreadsheet; instrumentation can come later. **Metric:** three baselines, dated, recorded before anything below ships. The order matters more than it looks: [METR's developers believed they were 20% faster while measuring slower](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/), so self-report is precisely the instrument this problem breaks. And a baseline you never took can't defend Move 6's budget when someone comes to reclaim it in Q3.

> Nobody believes the "it's better now" slide without the "it was this bad" slide.

With the three numbers dated, here is where the next eleven weeks go:

## Move 2: Give Every Module a Name (Weeks 2–4)

If [Naur is right that the theory lives in people](https://pages.cs.wisc.edu/~remzi/Naur.pdf) — and if [Storey's sharper framing](https://getdx.com/blog/cognitive-debt-the-hidden-risk-in-ai-driven-software-development/) is right that cognitive debt lives there too — then the map of your system's comprehension is a map of humans, and yours doesn't exist yet. Build it: every module gets a named human who can explain it. Explain, not approve — why the boundary sits where it sits, which invariant must hold, which similarity between two functions is meaningful and which is coincidence. The map lives in-repo next to CODEOWNERS — think of it as CODEOWNERS++ — so it diffs, gets reviewed, and rots in public instead of in a wiki nobody opens.

Two things happen immediately. First, orphans surface: the Move 1 orphan count stops being an estimate and becomes a list, and an orphan entry is not an embarrassment, it's the backlog. Second, code review changes meaning. A comprehension review is the reviewer explaining the diff back — two sentences on what it does and why it's safe — before approving it. [Anthropic's skill-formation study](https://arxiv.org/abs/2601.20245) found AI-assisted engineers scoring 17% lower on comprehension of code they had just shipped; explain-back is the cheapest known antidote, and it quietly converts review from a rubber stamp into a theory-transfer session.

> "The team owns it" is ownership in the passive voice — grammatically valid, nobody home.

**Owner:** the engineering manager. **Mechanism:** an in-repo ownership map plus explain-back review. **Metric:** orphan-module count, trending toward zero.

## Move 3: Ratchet the Boundaries (Weeks 3–6)

[Part 3](/blog/comprehension-debt-boundaries-beat-willpower) argued that boundaries beat willpower; the Monday version is strangler-pattern, not surgery. You do not re-architect anything. You write the boundary rules you wish were already true — dependency-cruiser or eslint-plugin-boundaries, the fitness functions from Part 3 — and enforce them on **changed files only**. Untouched legacy compiles in peace. But anything the feature train touches this sprint has to pass, and every sprint you promote one warning to an error. The ratchet clicks in one direction, and nobody ever schedules a big-bang migration, because there isn't one.

This move aims straight at the ugliest number in [GitClear's dataset](https://www.gitclear.com/ai_assistant_code_quality_2025_research): refactoring collapsed from 24.1% to 9.5% of changed lines while duplicated blocks rose 8x. Generated code does not respect module boundaries voluntarily, and no prompt engineering will make it. A rule that fails CI will — and the agents adapt to a red build faster than any junior you've ever onboarded, which is the one place their speed finally works for you.

**Owner:** a senior engineer who enjoys deleting imports. **Mechanism:** boundary rules enforced on changed files, ratcheted outward weekly. **Metric:** percentage of the codebase under enforcement — a number that only ever goes up.

## Move 4: Gate the New, Mine the Old (Weeks 5–8)

[Part 4](/blog/comprehension-debt-specs-with-a-failing-state) gave specs a failing state; [Part 5](/blog/comprehension-debt-metaframework) assembled them into a metaframework — typed, schema-validated entities living in git, with [a CI gate that exits 1 when the catalog lies](https://github.com/sergio-bershadsky/metaframework). The Monday mistake would be migrating the wiki into it. Don't. Bulk migration is re-serializing stale theory at scale: weeks of effort spent giving fiction a schema. Gate the new instead: from this week, every new decision, capability, and data model enters as a typed entity that validates in CI — or it didn't happen.

The old wiki gets demoted to read-only legacy and mined opportunistically. When real work touches an area, the module's named human (Move 2) either promotes the relevant page into a typed entity or leaves it to die with dignity. The knowledge that matters gets pulled through by actual work; the rest was ballast, and now you know which was which without holding a single migration meeting.

> The old wiki isn't wrong, exactly. It's historical fiction — based on true events.

**Owner:** the architect. **Mechanism:** typed entities plus CI validation for all new knowledge; a read-only stamp on the old. **Metric:** share of this quarter's decisions that entered through the gate.

## Move 5: Put the Rules File on a Diet (Weeks 7–9)

Your CLAUDE.md or AGENTS.md was [Part 2's](/blog/comprehension-debt-frozen-context) patient zero, and by this week Move 4 has removed its favorite excuse: decisions now have a validated home, so the rules file no longer has to be one. What remains should be the [smallest possible set of high-signal tokens](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) — not because minimalism is fashionable, but because [Chroma measured all eighteen frontier models degrading as context grows](https://www.trychroma.com/research/context-rot) and because bloated rules files get [ignored wholesale, not selectively](https://getunblocked.com/blog/audit-fix-bloated-claude-md/), with no observable event marking the moment your guidance became noise.

The mechanism is an expiry date. Every rule carries a review-by date; any rule past its date that nobody stands up to defend gets deleted. Delete beats append: rules that are really boundaries migrate to Move 3's enforcement, rules that are really decisions migrate to Move 4's entities, and rules that are really trauma responses to one bad Tuesday get to retire.

> Every rules file is one incident away from becoming a novel the agent skims.

**Owner:** whoever owns the agent tooling. **Mechanism:** expiry-review dates plus a standing deletion pass. **Metric:** rules-file token count trending down while agent task success holds.

## Move 6: Book the Budget (Weeks 9–12, Then Forever)

Everything above dies without this move, because everything above competes with features for the same hours. So stop letting it compete: reserve a standing percentage of every cycle — pick a number, defend it — for comprehension work: explain-back sessions, ratchet promotions, opportunistic entity promotion. Then report that work **next to velocity**, on the same dashboard, in the same meeting. What gets measured next to velocity gets protected from velocity; what gets reported in a separate "tech health" deck gets sacrificed to it by Thanksgiving.

This is not charity toward an abstract quality goal. [Comprehension consumed about 58% of engineering time before AI wrote a single line](https://ieeexplore.ieee.org/document/7997917/) — the budget doesn't add a cost, it books one you were already paying invisibly, at the worst possible moments. [DORA 2025](https://dora.dev/) shows the unbudgeted path's shape precisely: throughput up, stability down. And [Osmani's line from Part 1](https://addyosmani.com/blog/comprehension-debt/) was a job description all along: "The comprehension work is the job. AI handles the translation."

Every gauge on that dashboard is a Move 1 diagnostic, and every move above it exists to bend exactly one curve. **Owner:** the engineering manager and the product manager, jointly — this move dies if either defects. **Mechanism:** a protected slice of each cycle, visible on the roadmap itself. **Metric:** the three gauges, reported beside velocity, trending down.
